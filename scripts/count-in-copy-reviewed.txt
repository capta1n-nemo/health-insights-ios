# Counts written out in words, in reader-facing copy, that predate the lint.
#
# Read `scripts/verify.sh` ▸ "A hard-coded count inside reader-facing copy"
# first — it says what the rule is and why it is this narrow. This file is the
# ledger of what already existed when the rule arrived: every string the lint
# flagged on 2026-08-07, opened, checked against the code, and given a reason.
#
# ⚠️ **This is not where new copy goes.** New copy has two better answers, in
# order: derive the count from the collection — `\(out.channels.count) signals`,
# which cannot go stale — or, where the count is structural rather than the size
# of something, put `// count-in-copy: exempt — <why>` on the line. Both keep the
# reason next to the sentence, which is where the next reader will be. An entry
# here is a reason living three directories away from the thing it explains, and
# it is only defensible for strings that were already shipped.
#
# Format:  <path> | <matched fragment> | <why the count cannot go stale>
# The fragment is matched case-insensitively and line numbers are deliberately
# not used — they drift, and a ledger keyed on a drifting number silently stops
# matching, which reads as "clean".
#
# ## What the 2026-08-07 sweep found
#
# Seventeen flagged strings. **One was a live instance of the defect the rule
# was written for**: SustainedLoadInsight said "This measures four signals that
# load moves" on a card that runs on as few as two. It was fixed rather than
# entered here, which is what a first run of a lint should produce.
#
# Two more are the same *shape* and survive only because they are empty states,
# where the card has read nothing at all and is describing its own design rather
# than a reading — MentalHealthModel and HealthWatch below. Both enumerate their
# channels by hand, so both go stale the day a channel is added. They are
# entered, not fixed, because interpolating the count while leaving the names
# hand-written would make the sentence *internally* inconsistent, which is worse
# than the consistent staleness it has now. Fixing them properly means deriving
# both the count and the names, and that is a copy change with a reader-visible
# result rather than a lint's business.
